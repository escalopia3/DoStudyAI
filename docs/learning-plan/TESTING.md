# 测试门禁与证据

## 1. 测试等级

| 标签 | 验证什么 | 可以使用的替身 |
|---|---|---|
| U | 纯规则、schema、排序、状态转移、参数校验 | 可用 fake/mock；不能宣称数据库/服务集成通过 |
| DB | 唯一约束、事务、Outbox、租约、乐观锁、迁移 | 使用隔离 MySQL 8 实例/schema；H2 不能替代 MySQL ngram/锁语义 |
| INFRA | MQ、Redis、MinIO、Qdrant 的实际行为 | 独立测试 topic/bucket/collection；不能写用户数据 |
| UI | 页面行为、导航、权限切换、SSE 与旧界面 | 固定 API 响应可测交互；另需真实端到端 |
| MODEL | 真实模型质量、原文引用、无答案处理 | 固定回归集；mock 结果不能替代此等级 |
| LEGACY | 原视频、旧 API、扩展、历史数据 | 确定性契约测试 + 必需手动/端到端项 |

任务卡标明必需等级。每个等级分别记录 PASS / FAIL / NOT_RUN / BLOCKED，不用一个“测试通过”掩盖缺项。除 T00 的基线调查可把失败如实登记作为交付外，功能包必需验收不通过就不能设 DONE。

## 2. 已存在的命令

以下是项目当前配置确认过的入口；在对应目录执行，PowerShell 示例不拼接 shell 分隔命令：

| 标签 | 工作目录 | 命令 |
|---|---|---|
| OLD-BE | `server` | `.\mvnw.cmd test` |
| OLD-FE | `client` | `npm test` |
| BUILD-FE | `client` | `npm run build` |
| OLD-EXT | `extension` | `node --test` |
| FOCUS-BE | `server` | `.\mvnw.cmd "-Dtest=实际存在的测试类" test` |
| FOCUS-FE | `client` | `node --test src/实际存在的.test.js` |

Linux 用 `./mvnw`。执行前检查 JDK/Node、依赖及服务；缺依赖按环境权限处理，不能关闭测试或更改版本要求来制造绿色结果。

拟定新增 `TEST-CLI`：使用现有 Maven wrapper 的绝对路径，工作目录设为 `learning-parser`，指定该目录 POM 执行 test。T11 必须验证命令实际可运行，并写入证据；若 wrapper 对工作目录有假设，选择单独安装 Maven或合适的显式 `-f`，不能臆造可执行命令。

测试类名在任务卡中是设计建议，未创建前不是可运行的命令。新增前端 Node 测试放根 src 下以匹配现有脚本；组件测试框架/浏览器自动化如需引入，在 T10 冻结具体工具、版本和命令，不静默把原测试脚本替换成新框架。

## 3. 每包最小验证

1. 运行本包关键成功、边界及失败行为测试，并记录用例数量。
2. 触及公共接入面时跑对应旧回归；只写新内部纯规则时无需反复跑全部外部模型评估。
3. 数据修改包至少有双用户/跨课程越权验证和失败事务验证。
4. 产生异步副作用的包至少验证重复消息、取消或失败恢复中的相关路径。
5. 最终检查变更文件与允许范围，确认未改 `.env`、旧迁移、旧模型配置及无关文件。

仅文档任务检查链接/schema/依赖图，不为任务卡编写镜像式业务测试。

## 4. 阶段门禁

| 门禁 | 任务范围 | 必须给出的证据 |
|---|---|---|
| G0 基线 | T00～T02 | 旧测试/限制、契约样例校验、六类文档实际解析样本报告 |
| G1 基础 | T03～T10 | 开关关闭旧系统正常；任务租约/Outbox；课程归档不搬文件；原入口不受新模块影响 |
| G2 资料 | T11～T19 | 不建课导入、六格式及 OCR、超限/损坏失败、旧视频只读复用、原视频流程回归 |
| G3 笔记/知识库 | T20～T27 | 独立笔记、旧结果保存、发布回退、真 MySQL/Qdrant 检索、删除失效无越权 |
| G4 课程 Agent | T28～T30 | 工具有界、对话版本、真实笔记命中、引用与无答案、旧 Video Agent 回归 |
| G5 复习 | T31～T35 | 重点确认、题目答案不提前泄漏、评分幂等、未知掌握度、每日分钟数限制、用户应用新计划 |
| G6 发布 | T36～T37 | 固定集质量、混合负载、完整新旧回归、迁移和功能开关回退演练 |

每阶段末包负责把门禁报告登记到 STATUS.json.gates。前置门禁未通过时不得开启依赖它的用户能力；可继续无依赖的内部任务，但不能绕过失败依赖把功能发布。

## 5. 证据文件约定

使用 `evidence/Txx/<timestamp>-<check>.md` 或测试工具原生报告。至少包括环境、工作目录、原样命令、日期、退出码、执行用例数量、通过/失败/跳过数，以及失败摘要。

模型报告额外包含数据集版本、样本量、模型/提示词/工具版本、使用成本和错误分类。性能报告比较同机同负载的旧场景与混合场景，不用单次请求平均值代替 p95。

真实资料需获得使用授权，测试环境必须和用户数据隔离。不上传私有样本到仓库，不将密钥打印进日志。不能仅凭复制旧报告声称当前代码通过，报告须绑定 commit 或文件摘要。
