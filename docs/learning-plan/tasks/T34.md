# T34 · 复习计划与执行进度

> 阶段 F · 任务定义，不表示实现完成。实际状态只查 [STATUS.json](../STATUS.json)。  
> 前置任务：[T33](T33.md)。只有真实产物和必需证据齐全才可开始依赖它们的实现。

## 目标

按重点、薄弱点和可用时间生成可执行计划，并显式应用。

## 最小读取集

- [执行规则](../EXECUTION.md)、[契约登记](../CONTRACTS.md)、[测试门禁](../TESTING.md)。
- [技术设计](../../course-learning-technical.md) / [开发文档](../../course-learning-development.md) 中：技术 §9.2～9.3。
- 所有直接前置任务的交接及其实际公开接口；不存在的交接不能靠聊天补全。
- 当前代码核对：已确认 profile/topic、mastery、计划 schema。

## 修改范围

learning/review/planning、task progress、迁移/APIs/tests；启用 draftReviewPlan。

共享文件仅做任务明确需要的最小改动。未列出的必要支持文件先列入本包计划并说明理由；涉及旧契约、范围或其他包的公共接口时按变更规则处理，不静默扩大任务。

## 实施检查点

1. 确定性规则分配每日分钟数，未知项先诊断；模型负责说明与材料组合。
2. 计划版本/应用/替代、完成/跳过/实际用时保存；预算不足返回未排入项。
3. 新答题结果只建议优化，不静默替换当前计划；考试日期/时区边界测试。

每完成一个检查点就保存已验证事实；上下文不足时更新交接后继续当前包，不跳到后续任务。

## 必须交付

- 计划生成/读取/应用与任务进度 APIs、工具实现。
- `handoffs/T34.md` 与该包实际证据路径。
- STATUS.json 中真实状态、验证结果和下一包；不复制其他包的报告作为本包结果。

## 验收

- [ ] 每日时长不超用户预算；已完成历史在新计划应用后仍保留。
- [ ] 证据无效的材料不推荐；模型不能绕过时间/权限规则。
- [ ] 修改范围和原功能兼容检查通过。
- [ ] 必需验证已执行且可复现，未执行项明示。
- [ ] 交接中的公开接口名称、路径及迁移号与代码一致。

验证要求：DB + U + 完整复习后端端到端。

命令选择按 TESTING.md 执行；建议测试类名/目录是待创建产物，先核实再运行。记录工作目录、原样命令、退出码、用例数量、环境及代码摘要。集成/模型检查缺环境时保留 VERIFY_PENDING 或 BLOCKED，不改测试条件制造通过。

## 不做与停止边界

不加邮件/短信/自动通知或跨课程全局调度。

当前包完成后停止；默认不自动执行下一包。发现依赖和代码不符时记录差异，暂停依赖该事实的工作，不能编造“已有服务”。
