## 修改范围

docs/learning-plan/contracts/、DECISIONS.md；本包不写生产 Java/Vue 或执行 DDL。

共享文件仅做任务明确需要的最小改动。未列出的必要支持文件先列入本包计划并说明理由；涉及旧契约、范围或其他包的公共接口时按变更规则处理，不静默扩大任务。

## 实施检查点

1. 按 CONTRACTS 登记创建 OpenAPI、五类 JSON Schema、有效/非法样例及 schema-plan。
2. 明确空值、ID、scope、状态、membership_version、错误码、分页、幂等及来源版本；修正主设计中的示例 DTO 不完整处，并登记决策。
3. 冻结分阶段的表归属、端点归属和异步失效事件；选择可实际执行的 schema 校验工具并记录命令。

每完成一个检查点就保存已验证事实；上下文不足时更新交接后继续当前包，不跳到后续任务。

## 必须交付

- 机器可读契约、示例、校验报告和 SHA-256 清单。
- `handoffs/T01.md` 与该包实际证据路径。
- STATUS.json 中真实状态、验证结果和下一包；不复制其他包的报告作为本包结果。

## 验收

- [ ] 所有样例实际通过/拒绝符合预期；OpenAPI 所有引用可解析。
- [ ] 无 courseId 的独立资料合法；跨课程引用非法；没有把旧接口字段改成新约定。
- [ ] 修改范围和原功能兼容检查通过。
- [ ] 必需验证已执行且可复现，未执行项明示。
- [ ] 交接中的公开接口名称、路径及迁移号与代码一致。

验证要求：U（schema）；契约校验命令由本包选定并记录，未运行不得完成。

命令选择按 TESTING.md 执行；建议测试类名/目录是待创建产物，先核实再运行。记录工作目录、原样命令、退出码、用例数量、环境及代码摘要。集成/模型检查缺环境时保留 VERIFY_PENDING 或 BLOCKED，不改测试条件制造通过。

## 不做与停止边界

分三个检查点：资料/任务 → 笔记/索引 → Agent/复习；不能引入新产品范围。

当前包完成后停止；默认不自动执行下一包。发现依赖和代码不符时记录差异，暂停依赖该事实的工作，不能编造“已有服务”。
