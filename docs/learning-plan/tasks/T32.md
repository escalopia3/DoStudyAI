## 修改范围

learning/review/practice generation、题表迁移/接口/tests；启用 draftPractice。

共享文件仅做任务明确需要的最小改动。未列出的必要支持文件先列入本包计划并说明理由；涉及旧契约、范围或其他包的公共接口时按变更规则处理，不静默扩大任务。

## 实施检查点

1. 单选/判断题生成、唯一答案与来源校验；失败题不投放。
2. 题目读取 DTO 不含答案/解析；服务端保存答案，明确 AI 生成来源。
3. 来源失效停止投放；简答题只作参考/自评，首版可在 UI 后置。

每完成一个检查点就保存已验证事实；上下文不足时更新交接后继续当前包，不跳到后续任务。

## 必须交付

- 真实题目生成 job、读题 API、工具实现。
- `handoffs/T32.md` 与该包实际证据路径。
- STATUS.json 中真实状态、验证结果和下一包；不复制其他包的报告作为本包结果。

- [ ] 客户端请求和响应中无提前答案；工具 count/难度受限。
- [ ] 无原文支持的题被拒绝，重复生成任务不重复入库。
- [ ] 修改范围和原功能兼容检查通过。
- [ ] 必需验证已执行且可复现，未执行项明示。
- [ ] 交接中的公开接口名称、路径及迁移号与代码一致。

验证要求：DB + U + MODEL 小型题目审核。

命令选择按 TESTING.md 执行；建议测试类名/目录是待创建产物，先核实再运行。记录工作目录、原样命令、退出码、用例数量、环境及代码摘要。集成/模型检查缺环境时保留 VERIFY_PENDING 或 BLOCKED，不改测试条件制造通过。
