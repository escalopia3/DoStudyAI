## 先看这一页

本升级保留原视频所有功能，再增加独立文档、课程分组、学习笔记、课程 RAG 和复习。为减少 AI 上下文偏离，拆为 **38 个任务包（T00～T37）**，默认一次只完成一个包。

每包一般只负责一个领域结果；涉及多项职责时按卡片中的检查点分次完成，不以一次聊天必须做完为目标。任务数量不是工期，整体工期仍以[开发文档](../course-learning-development.md)估算为准。

## 开发顺序

| 阶段 | 任务包 | 完成后能看到什么 |
|---|---|---|
| A 基线与契约 | T00～T02 | 旧功能基线、契约和真实解析样本可行性 |
| B 新模块与课程基础 | T03～T10 | 开关隔离、可靠任务、课程归档和新入口 |
| C 多资料接入 | T11～T19 | PDF/Word/PPT 与旧视频进入独立资料库 |
| D 笔记与知识库 | T20～T27 | 笔记保存/编辑/发布、混合检索、删除失效 |
| E 课程专家 | T28～T30 | 使用笔记和原文、带出处的课程问答 |
| F 复习闭环 | T31～T35 | 确认重点、自测、薄弱点与可执行复习计划 |
| G 系统验收 | T36～T37 | 质量报告、原功能回归、负载和回退演练 |

表中按编号执行是一条可行的串行路径；真实前置条件以 STATUS.json 的 dependsOn 和任务卡为准。某卡完成不代表整阶段可发布，须通过对应测试门禁。

## 每次给 AI 的最短指令

> 按 docs/learning-plan/README.md 开始。核实 STATUS.json 和上一包交接，只执行当前 nextTaskId 的任务卡。遵守 EXECUTION.md、CONTRACTS.md 和 TESTING.md。不要实现后续任务，也不要把未执行的测试标为通过。完成后更新当前任务状态和交接文件，并停止在本包边界。

首次应执行 **T00：原功能基线**。当前全部任务均为 TODO，未启动业务开发。

更新任务后，可在项目根目录运行 `& .\docs\learning-plan\validate-plan.ps1`。它只校验计划结构与证据文件存在性，不会运行业务测试，也不能证明报告内容真实。

## 不偏离的五条硬约束

1. 原视频接口、模型、历史数据、模式、MQ/SSE 和浏览器扩展继续兼容。
2. 资料可以独立使用，课程是可选归档，不强迫用户先建课。
3. 保存笔记不等于发布知识库；发布笔记须有可核验原始来源。
4. 新课程 Agent 与旧 Video Agent 并存，禁止借机整体重写旧 Agent。
5. 以实际代码、测试和交接证据判断完成度；发现设计与代码不符时先记录差异，不能默默发明实现。
