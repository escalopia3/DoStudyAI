# 单任务执行规则

> 本文属于旧 T 系列计划，当前执行入口为 [课程工作台 v2](../course-workbench-v2.md)。不得用下述旧规则覆盖新版产品入口、接口或 W 系列任务范围。

## 1. 信息优先级

用户最新明确指令优先。随后按产品开发文档 v1.1 → 技术设计 v1.1 → 本目录契约登记及被采纳决策 → 当前任务卡阅读。任务卡是分解，不得改变上层范围。实际代码是当前实现状态的证据，不能用未来设计假装依赖已经存在。

如果契约间矛盾会影响数据、权限、旧行为或接口，记录具体冲突和最小修正建议；继续可独立验证的工作，暂停依赖该决策的写入。无需为普通命名、私有函数拆分等局部选择重复请求用户确认。

## 2. 开始一包的必做检查

1. 读取 README、STATUS.json、当前任务卡，以及 EXECUTION/CONTRACTS/TESTING。主文档只读任务卡指定章节，不必每次加载全部历史。
2. 读取所有直接前置任务的交接，核实其状态为 DONE，且产物确实存在、公开契约符合预期。跨模块调用检查真实方法和类型，不靠回忆。
3. 检查工作区未提交/未记录变化。当前工作目录在前次检查中不是 Git 仓库：执行时重新确认；若仍无 Git，用文件清单和 SHA-256 记录任务前后变化，不自动 `git init`、提交或重置文件。
4. 列出本包将修改的文件与测试。允许范围外的必要公共改动必须说明原因，检查影响并记录；业务范围扩大或旧契约变动须作为单独决策，不夹带。
5. 将本包设为 IN_PROGRESS，登记 sessionLabel、startedAt 和前置证据。默认只允许一个 IN_PROGRESS 包，不自动创建并行任务。

在未完成前置任务时，不得用生产代码中的假实现跳过依赖。测试中的 fake/mock 必须清楚命名，仅服务于边界验证；不把 mock 的成功当作真实基础设施或模型的成功。

## 3. 实施循环

按“检查真实调用点 → 小范围实现 → 执行有意义的行为测试 → 检查副作用 → 保存交接”推进。任务卡中的测试名是待创建/核实的建议名，调用命令前确认文件存在，防止 Maven/Node 实际没有执行到测试。

按需新增 Flyway 迁移，修改前重新查看最大版本号。迁移号码由当前任务登记，不在多张卡里预占相同 V4。禁止改已执行迁移，禁止把所有未来表一次建完。

约定新增代码根路径：

- Java：`server/src/main/java/com/example/server/learning/`。
- Java 测试：`server/src/test/java/com/example/server/learning/`。
- 前端：`client/src/learning/`；首版 Node 测试放 `client/src/learning*.test.js`，以被现有 `src/*.test.js` 脚本发现。
- 解析 CLI：`learning-parser/`，独立 POM；不把整个现有工程改成 Maven 多模块。
- 验收材料：`docs/learning-plan/evidence/`、`handoffs/`。

这些目录目前大多尚不存在，由相应任务创建。包内可以按职责细分，不要求把实现全部放在一层。

## 4. 状态与完成条件

| 状态 | 含义 | 是否可作为下一包前置 |
|---|---|---|
| TODO | 尚未开始 | 否 |
| IN_PROGRESS | 当前正在实现 | 否 |
| VERIFY_PENDING | 实现已写，但必需验证未完成 | 否 |
| BLOCKED | 缺少必需环境/输入/决策，具体原因已登记 | 否 |
| DONE | 卡片交付物存在、该包必需测试通过、交接和台账更新 | 是 |

这里是开发台账状态，不是运行时 learning_jobs 状态，也不调用会话目标管理工具。允许同一包跨多个会话持续完成。环境不可用时如实保留 VERIFY_PENDING/BLOCKED；不得写“应该通过”后设 DONE。

DONE 必须同时满足：

- 本卡验收项全部得到证据；与本卡无关的系统级门禁可留到指定后续任务。
- 新代码不依赖未实现的生产 stub；尚未具备端到端能力的功能入口仍关闭。
- 本次变更没有新增相关旧功能回归，公共接入面执行对应旧测试。
- 清楚记录修改文件、迁移版本、测试命令、工作目录、退出码、测试数量和结果位置。
- 产出 `handoffs/Txx.md`，更新 STATUS.json，再将 nextTaskId 指向编号最小且前置均 DONE 的 TODO 包；无可执行包时设 null 并说明原因。

文档和任务实现验收不能自动等同于整阶段发布：TESTING.md 的阶段门禁是额外检查。

开始执行时将 nextTaskId 设为 null，currentTaskId 设为当前包；结束后才选择下一包。中断而未 DONE 时保留 currentTaskId 指向待恢复包，避免新会话误开下一包。checks 条目使用 `id / required / status / command / workingDirectory / exitCode / testCount / evidence`，evidence 为相对本计划目录的报告文件数组。报告型任务 T00 可把“完整记录基线”作为必需 PASS 项，同时将发现的失败测试独立登记为 FAIL，不能改变原测试事实。

每次更新台账运行 validate-plan.ps1；结构通过不等于测试通过，人工仍须核对必需测试是否漏填。本轮第一次业务任务开始时将 businessImplementationStarted 设 true，记录真实时间。

## 5. 上下文交接

每次中断前更新交接，即使包未完成。最少包括：已经验证的事实、当前未完成步骤、失败的原始错误摘要、下次第一条动作、需要阅读的确切文件。不要复制完整聊天历史，也不要把猜测写成事实。

跨会话恢复只认已落盘资料；先核实文件变更，不能因上一条聊天说“完成”就跳包。测试证据可保存简短日志或报告，不保存密钥、用户私有资料或整个 `.env`。

状态台账允许记录工作区快照摘要。Git 可用时记录 commit 与 dirty 文件；不可用时记录变更文件 SHA-256 清单，不虚构 commit。

## 6. 契约变更

公共 DTO 字段、API、迁移结构、状态机、删除语义、模型工具 schema 均属于契约。先在 DECISIONS.md 追加提案，列出影响任务与迁移/兼容策略；涉及用户范围变化时等待明确决定。局部且符合既定方案的细化可记录后直接实施。

决策被采纳后，同步更新契约文件、当前任务及被影响的未完成卡片。已经 DONE 的任务若被修改，其相关测试必须重跑；不能只改文档宣称兼容。契约文件的 SHA-256 在 T01/后续修订交接中登记，后续 AI 发现不一致须先核查原因。

## 7. 必须停在边界的情况

- 下一步需要改旧 API/消息/状态格式或覆盖原视频分析结果。
- 后续模块尚未具备，而当前功能必须依赖它才能真实成功。
- 缺少模型凭证、测试服务或授权资料，无法完成卡片要求的真实验证。
- 发现迁移、删除或权限规则相互冲突，继续实现可能导致数据损失/越权。
- 已完成当前包。除非用户明确授权连续执行，否则交接后结束，不顺手实现下一包。

停下时说明已完成内容、具体阻塞和下一步，不把所有常规实现决策都转成用户审批。
