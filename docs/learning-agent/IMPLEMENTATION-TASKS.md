# 学习 Agent：可逐项编码的小需求

> 基线：[开发方案 v1.2](../learning-agent-development.md) · 2026-10-14  
> 以下为任务规划；实现状态及未验证项以 STATUS.json 为准，不将代码已写等同于生产验收通过。

## 1. 执行约定

LA00–LA15 是里程碑模块，下表子任务才是一次编码工作的边界。每项只引入一个可验证行为；不要在一个任务里完成整个 Agent。默认按依赖顺序执行，无需同时启动多个开发 agent。

每项交付必须包括：实现文件、契约/迁移变化、测试命令和结果、真实服务验证证据、限制、下一项入口。状态使用 TODO → IN_PROGRESS → DONE；缺依赖记 BLOCKED 并说明缺口。未跑检查写 NOT_RUN，不把测试代码存在当作测试通过。

Python 全权负责新增知识链路，包括向量和词法索引。Java 只处理业务身份、权限、原文件、会话、记忆真源和状态投影。新 Python 功能不修改旧 Java 视频检索行为。

## 3. 生产实现必须明确的细节

### 3.1 状态与一致性

- sourceRevision 由 Java 确定；indexRevision、活动索引及快照由 Python 确定。不要把 UI 的 READY 当作查询许可。
- Python 本地发布事务只覆盖自身 MySQL；Qdrant/MinIO 使用先构建不可变产物、验证、再发布指针的流程。失败孤立产物可回收，未发布不可检索。
- 处理租约附带单调 fencing token；过期执行不能发布、回调或续写活动状态。
- 所有跨服务写入支持幂等键和事件序号；至少一次投递配合幂等，不宣称端到端 exactly-once。
- Python 知识 outbox 与 Java 业务 outbox 各自拥有独立重试和告警；达到重试上限进入可人工重放状态。

### 3.2 授权与撤销

Java 返回的授权范围是可信服务数据，不能由前端直接控制。Python 在读取证据/构建上下文前复核；Java 在最终提交事务内检查 scopeVersion 和来源。请求开始时合法、生成期间被撤销的资料不能出现在最终结果中。已经发送给模型的上下文无法追溯撤回，因此不承诺撤权可撤回在途外部调用。

scopeVersion 必须随课程关联、资料删除和原文件版本变动递增。权限查询故障返回明确错误；缓存只能降低普通读取成本，不能绕过最终授权检查。首版限制单课程资源数量和单次授权范围大小，超过上限明确返回错误，禁止静默丢弃过滤条件。

### 3.3 并发、重试与可恢复性

按租户与全局分别限制解析、embedding、LLM 和 MCP 并发。请求超时与任务总 deadline 分开配置；所有自动重试共享剩余预算。API 进程不承担长期任务，worker 优雅退出时停止领取并妥善处理租约。

依赖降级规则：Qdrant 整体故障时检索失败，不能假设另有 MySQL 关键词索引；仅某召回通道故障且活动版本与授权仍可验证时，可使用另一通道。知识数据库整体不可用、无法确认活动版本或权限服务故障时必须停止；模型故障返回失败并保留可重试运行，不能伪造答案。

### 3.4 发布、迁移和运维

迁移作为发布步骤单独执行，不由多个 worker 同时启动迁移。独立配置开发/测试/生产数据前缀与凭证。先备份、部署兼容新增字段、验证，再开功能开关；回滚关闭入口并保留可恢复数据。

指标至少包括：任务队列年龄、租约过期数、outbox 延迟、解析失败率、索引版本、召回空结果率、首事件/最终答案延迟、模型 token/费用、取消响应、记忆合并冲突和 MCP 可用率。日志关联 traceId/jobId/runId，不记录密钥和完整私人资料。
