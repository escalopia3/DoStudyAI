## 1. 要做成什么

在现有 DoVideoAI 上增量升级：原视频功能完整保留，新增 PDF、Word、PPT 等资料的知识提炼与笔记保存，再增加可选的课程归档、课程知识库和期末复习 Agent。用户既可以继续单独分析视频，也可以只上传一份 PDF 生成笔记，不必创建课程。

学生需要系统学习时，把视频、讲义、课件和复习范围归入同一课程文件夹，系统利用保存的学习笔记及其原始出处构建课程知识库，并在期末根据考试范围、课程重点和个人薄弱点安排复习。

典型场景：创建“数据结构”课程 → 添加第 1～12 讲视频、PDF 讲义和 PPT → 按章节生成笔记 → 上传老师的考试范围 → 做一轮自测 → 得到每天的复习任务和针对性练习 → 根据答题结果调整后续复习。

“课程专家”是一套绑定该课程资料、笔记和学生学习记录的 Agent 配置。新增资料后更新检索索引即可，不需要为每门课训练一个模型。其回答范围受已上传资料约束；资料不足、存在冲突或识别不清时应明确说明。

### 1.1 原功能保留是发布门槛

| 原有能力 | 升级后的约束 |
|---|---|
| 注册、登录、退出及用户隔离 | 使用现有账号与会话，无需重新注册 |
| 本地视频上传、分片、断点续传、在线视频链接导入 | 原流程、限制、错误行为和接口保持兼容，无需选课程 |
| 视频列表、播放、删除、时间戳跳转 | 原记录、链接及操作继续可用 |
| 通用、学习、审查、创作与自动路由 | 保留原视频模式和产物，课程 Agent 独立增加 |
| 视频转写、MP3 导出、证据搜索、追问历史 | 原入口继续存在，课程功能不成为前置条件 |
| 分析计划、反馈修订、评估和阶段轨迹 | 原有结果和操作可读可用 |
| MQ 分析、SSE、检查点、失败重投 | 原消息格式、状态和恢复逻辑不被新任务覆盖 |
| 浏览器扩展及前端 `?demo` | 旧客户端无需升级即可继续使用原后端契约 |

新增能力关闭时，用户仍可完整使用上述功能。新增解析失败、课程索引失败不能把原视频标记为失败或覆盖其分析结果。实现阶段每次交付都必须通过兼容回归；文档设计不能替代这一验证。

## 2. 本期方案的五个决定

| 决定 | 用户得到什么 | 实现收益 |
|---|---|---|
| 一个课程对应一个逻辑文件夹，下面按章节组织 | 同课资料集中，章节顺序可调整 | 无需移动 MinIO 中的实际文件 |
| 新增统一资料入口，课程分组可选 | 视频和文档都可单独使用，再按需归档 | 视频保留原业务真源，文档使用新增资料模型 |
| 笔记保存不可变版本和引用 | 可以编辑、回看旧版本、跳转原始出处 | 修改不会覆盖旧答案的证据 |
| 笔记和原始资料一起参与 RAG | 先获得整理后的解释，必要时核验原文 | 减少只检索摘要造成的信息损失 |
| 一个课程 Agent 配备多个受控工具 | 能搜索、查原文、出题、安排复习 | 复用现有 Java 技术栈和任务体系 |

## 3. 功能范围与交付边界

### 3.1 第一版必须完成

| 功能 | 首版行为 | 通过标准 |
|---|---|---|
| 课程管理 | 新建、重命名、归档、删除；设置学期、课程简介 | 不同用户看不到彼此课程 |
| 章节管理 | 创建、改名、排序；允许资料暂未分章 | 一个课程中的资料可以按章节浏览 |
| 视频归档 | 新视频进入指定课程；已有视频可关联到课程 | 原视频播放和分析仍然可用 |
| 独立资料处理 | 不建课程也可导入文档、按要求提炼知识和保存笔记 | 新文档不依赖课程创建；原视频不要求迁移 |
| 文档导入 | PDF、DOCX、PPTX；DOC、PPT 提供基础文字兼容 | 显示明确的解析状态和能力限制 |
| 学习笔记 | 按用户要求生成单资料、章节、整课笔记 | 保存版本，有引用，可编辑、导出 Markdown |
| 课程知识库 | 将可用原文及发布的笔记纳入本课索引 | 清楚显示当前可用资料数与更新状态 |
| 课程问答 | 新增课程 Agent，跨本课已发布笔记及原始资料回答 | 不覆盖原 Video Agent，不混入其他课程或用户资料 |
| 课程重点 | 用户填写/导入考试范围，并确认知识点对应关系 | 区分明确重点和系统建议重点 |
| 针对性复习 | 考试日期、每天可用时间、诊断题、复习计划、错题回练 | 能解释每项复习任务的安排原因 |

### 3.2 文档支持分级

| 格式 | 首版承诺 | 不承诺的能力与处理方式 |
|---|---|---|
| 视频 | 复用 ASR、OCR、时间戳证据 | 无文字动作理解暂不保证 |
| 文本 PDF | 逐页提取文字，引用 PDF 页码 | 多栏、复杂表格可能有阅读顺序偏差，提供预览和告警 |
| 扫描 PDF | 对无有效文字的页面执行中英文 OCR | 手写、复杂数学公式不保证；低质量页标记待确认 |
| DOCX | 段落、标题、列表、普通表格 | 引用标题路径和段落编号，不虚构 Word 页码 |
| PPTX | 按幻灯片提取文字、普通表格、备注 | 图片型图表、SmartArt、动画可能丢失信息，明确提示 |
| DOC / PPT | 基础正文/幻灯片文本解析 | 复杂排版失败时提示转换为 DOCX/PPTX 或 PDF；不得静默生成空笔记 |

正式首版包含上述格式，但按“现代格式优先、旧格式兼容后补”的顺序交付。解析完成后先展示原文预览和质量提示，避免用户在不可用的识别结果上继续消耗模型额度。

### 3.3 后续迭代

- 图片、手写笔记与公式专项识别，图表和操作画面的视觉理解。
- 多层任意文件夹、跨课程复用资料、多人共享课程。
- 高质量 Word/PDF 笔记导出、Office 在线原版式预览。
- 更多题型、间隔重复提醒、跨课程复习日程。
- 外部网络资料补充、知识图谱和模型微调：仅在评估证明需要时再引入。

## 4. 页面和操作流程

### 4.1 页面结构

```text
现有工作台（默认入口保留）
├── 原视频工作台：原有操作完整保留
├── 全部资料：视频 / PDF / Word / PPT，可不归属课程
├── 我的笔记：单资料笔记与课程笔记
└── 我的课程
    └── 数据结构（12 份资料 / 8 篇笔记 / 知识库更新中）
        ├── 资料：全部 / 按章节 / 未分章
        ├── 笔记：资料笔记 / 章节笔记 / 整课笔记
        ├── 课程专家：对话、引用、资料覆盖范围
        └── 期末复习：考试范围、知识点、自测、计划、错题
```

课程文件夹是可选业务分组，第一版只提供“课程 → 章节 → 资料”三层结构。独立资料导入与笔记生成在全部资料中完成；跨资料课程问答和复习在课程内完成。保留原首页和已有链接，不把课程首页强制替换为默认首页。

### 4.2 导入资料

1. 用户在全部资料或课程内拖入一个或多个文件。前者可不选课程；后者默认归入当前课程，章节可选。
2. 页面显示逐文件上传进度；视频沿用分片上传，文档使用独立上传接口。
3. 文档上传后开始解析，归课后再建立课程索引；新入口的视频显式启动学习提取，原视频上传不增加自动解析副作用。页面展示本次实际执行的阶段。
4. 用户可以先使用已经就绪的资料；失败资料单独显示错误和重试入口。
5. 资料卡展示文字预览、来源类型、页数或时长、解析质量、知识库可用状态。

用户在原视频库中选择“加入课程”时关联已有视频，不重新上传。新入口上传视频仍调用原视频上传链路，成功后再关联课程；关联失败时视频已保存，页面允许重试归档。首版一份资料同时归属至多一个课程；同课多章节以主要章节归档，任意多课程复用放到后续版本。

移出课程只解除分组：原文件、原视频分析和单资料笔记继续存在；旧课程不再检索这份资料。全部资料页汇总旧视频与新增文档，未被使用的旧视频无需提前迁移或批量重新分析。

### 4.3 生成和保存笔记

1. 用户选择一份资料、一个章节或整门课程。
2. 输入要求，例如“重点整理概念和易错点，少写背景介绍”。
3. 系统显示本次覆盖的资料，以及尚未就绪、不会纳入的资料。
4. 笔记生成后自动保存为草稿；展示章节、知识点、例子、易错点、引用及未解决问题。
5. 用户点击“发布到课程知识库”。发布时系统校验引用；不满足条件的段落保持草稿或标记为个人补充，不作为可靠课程证据。
6. 修改已发布笔记时创建新草稿；上一发布版继续可用，新版发布并完成索引后切换。

未归课的单资料笔记一样自动保存、可编辑和导出。此时“发布”表示通过校验、可纳入知识库；加入课程后才构建该课程索引。不要求发布才能保存或阅读笔记。

原视频学习模式旁增加“保存为学习笔记”。能够定位原始证据的结果转换为笔记草稿；旧结果缺少可核验引用时照样保存并提示补充校验，不重新覆盖原分析结果，也不自动把它当作课程可靠证据。

首版笔记编辑采用 Markdown 编辑和预览。每次保存生成版本；恢复旧版也生成一个新版本，不删除版本历史。个人补充可以保存，但未经来源核验的内容不作为课程 Agent 的事实依据。

整课笔记按章节先提取、再合并。界面展示覆盖章节和遗漏资料，避免只用最相似的几段内容冒充整课总结。

### 4.4 使用课程专家

例：“二叉搜索树和堆有什么区别？结合这门课的例子解释。”

系统在当前课程中检索笔记与原文，回答后展示引用卡：视频 12:30、PDF 第 8 页、PPT 第 15 张或 Word 的章节与段落。证据不足时提示缺少什么资料；资料冲突时并列展示，不擅自消除冲突。

“课程专家”页面显示已纳入资料数、已发布笔记数、知识库更新时间和不可用资料。至少有一个可用来源即可进行问答，不必等待所有资料完成；尚无发布笔记时标为“仅基于原始资料”。笔记发布后明确显示该版本是否已被索引，用户能确认 Agent 确实使用了保存的笔记。

### 4.5 针对性期末复习

1. 用户填写考试日期、每天可用分钟数、目标和老师划定的范围。
2. 系统提取候选知识点和重点，用户确认范围和重要程度。
3. 用户进行短诊断测验；也可跳过，此时个人掌握程度显示“未知”。
4. 系统把范围内知识点分配到每天，安排阅读笔记、回看证据、自测和错题复练。
5. 用户完成题目后保存结果；系统更新薄弱点，生成后续计划的新版本。
6. 新计划需要用户应用；正在执行的计划不会因一次回答被静默替换。

重点依据的优先顺序：用户确认的老师考试范围 → 用户手工标记 → 有来源的教学目标 → 系统推测。系统推测标为“建议重点”，不能显示成“老师必考”。

首版自动判分只覆盖单选、判断等有明确答案的题。简答题提供参考答案和自评，不自动据此下调掌握度。题目应说明是 AI 生成练习，不冒充历年真题。

## 5. 数据和行为约定

- 课程、资料、笔记、对话和复习记录均为用户私有。
- 新资料在同用户下检测重复并提示复用；原视频上传去重行为保持兼容，不借本次升级改写。
- 从课程移除资料立即停止该课程的新检索；旧回答保留文字，但引用显示“来源已移出课程”。资料本身及单资料笔记仍在个人资料库。
- 原文版本改变或在个人库删除时，依赖它的笔记标记“需要更新”；只移出课程时，该课的相关内容失效，独立单资料笔记仍有效。
- 笔记、问答与复习计划保留生成时的来源版本和模型配置版本。
- 删除课程先逻辑删除并立即禁止访问，后台清理该课程索引、课程/章节笔记、对话和复习记录；原视频、文档和单资料笔记保留为未归课内容。首版不提供回收站入口，界面必须清楚列出保留项和删除项。
- 在个人资料库删除原文档，或在原视频库删除视频，才会使该来源及依赖它的笔记引用全局失效。资料删除和移出课程是两个不同操作。
- 模型运行中可以取消；已完成的资料解析成果可以保留，未完成答案不能标记为成功。

## 6. 分阶段开发计划

以下为熟悉项目的一名全职全栈开发者的初步工作量，不含长期模型调优；外部 API、复杂样本和部署环境会影响进度。可以按阶段验收，不应把全部需求合并为一次大提交。

| 阶段 | 工作内容 | 可演示成果 | 估算工作日 |
|---|---|---|---|
| P0 设计验证 | 建立旧功能回归基线；验证真实格式样本、中文检索与资源隔离 | 兼容基线、样本报告与依赖锁定 | 4～5 |
| P1 资料与课程基础 | 统一资料视图、可选课程/章节、旧视频懒关联、权限 | 原视频照常用，可加入/移出课程 | 5～7 |
| P2 多格式资料 | 独立文档导入、现代及旧格式、扫描 PDF OCR、任务恢复 | 不建课也能提取知识原文 | 8～11 |
| P3 笔记与知识库 | 单资料笔记、旧结果保存、课程笔记、版本发布、索引与失效 | 保存笔记后供课程 Agent 使用 | 7～10 |
| P4 课程 Agent | 跨资料检索、工具、引用、对话与预算、混合负载验证 | 新课程 Agent 与原 Video Agent 并存 | 6～8 |
| P5 复习闭环 | 重点确认、自测、计划执行记录、错题、全量回归和发布演练 | 针对薄弱点复习，原功能回归通过 | 8～11 |

合计约 38～52 个工作日，约 8～11 周；在原估算上补入独立资料入口、旧结果保存、完整兼容回归和发布演练。这是规划估算，不是交付承诺。P4 完成后可内测，P5 完成后验收全部新增需求。

每个阶段同时交付权限测试、失败恢复测试、基本界面状态和对应迁移脚本。P0 不通过的文档类型必须先修正处理方案或明确限制，不能以空文本成功绕过。

## 7. 验收清单

### 功能验收

- [ ] 新建两个课程，同名文件不会互相串数据。
- [ ] 关联旧视频不触发重复上传，原有视频分析仍正常。
- [ ] 不创建课程也可继续全部原视频操作，并导入文档生成、保存和导出笔记。
- [ ] 同一资料加入/移出课程不删除文件、不丢单资料笔记、不修改原视频分析结果。
- [ ] 原学习模式结果可以保存成新笔记；缺少出处的历史结果不会直接成为可靠 RAG 证据。
- [ ] PDF、DOCX、PPTX、DOC、PPT 和扫描 PDF 各有成功与失败样本。
- [ ] 引用可定位到正确的视频时间、PDF 页、幻灯片或段落。
- [ ] 笔记刷新页面后仍存在；编辑、发布、历史版本和 Markdown 导出可用。
- [ ] 整课笔记展示覆盖范围，未处理的资料不会被宣称已总结。
- [ ] 课程问答能同时引用两种资料；没有依据时承认不足。
- [ ] 修改和删除资料后，检索不再返回失效内容。
- [ ] 可导入考试范围，确认重点，并生成符合每天时间上限的复习计划。
- [ ] 答错客观题后，相关知识点获得后续练习任务；跳过自测时不虚构掌握度。

### 工程验收

- [ ] 双用户越权、跨课程检索泄漏测试全部通过。
- [ ] 重复 MQ 消息不产生重复笔记版本或重复答题计数。
- [ ] Worker 重启、模型超时、Qdrant 暂停后任务能恢复或明确失败。
- [ ] 索引更新失败时上一可用版本仍可查询；首次索引失败明确显示不可用。
- [ ] 任务能够取消，超预算后停止后续调用，错误原因可追踪。
- [ ] 文档解析有大小、页数、解压量、进程内存和执行时间限制。
- [ ] 固定评估集能输出质量、成本和延迟报告；未达阈值不扩大发布范围。
- [ ] 原视频四模式、自动路由、转写、MP3 导出、追问、修订、失败重投、扩展和 Demo 全量回归通过。
- [ ] 关闭新增功能开关后，旧 API 和旧界面仍可使用；旧 MQ 消息与检查点可正常恢复。
- [ ] 文档任务占满新增队列时，旧视频接口仍能受理；新增任务限流不得修改旧限流键或耗尽旧执行线程。
- [ ] 新文档 50 MiB 限制只作用于文档接口，不下调旧视频上传限制。

## 8. 首版成本和限制

主要成本来自视频 ASR、扫描页 OCR、初次生成笔记和模型问答。原文解析结果与 Embedding 按内容版本复用；修改笔记不重新解析视频，调整复习日期不重新生成全部知识。

首版对单课程的资料数、索引块数和文档大小设置可配置上限，具体默认值见技术文档。超限要明确提示，不能静默截断后生成“完整笔记”。本期沿用已有中间件，新增 PDFBox 和 POI 依赖，以及受限的文档解析进程。

复杂数学公式、图片图表、模糊扫描件的准确理解是后续专项。首版优先做到来源透明、失败可见、结果可修改和学习流程完整。

## 9. 开发开始前的默认假设

本方案已采用可直接排期的默认值：保留原入口和原契约、独立资料可用、课程归档可选、个人课程、单层章节、中英文资料、Markdown 笔记、用户确认考试范围、客观题自动判分、单节点起步。原视频审查和创作模式完整保留；新文档首版承诺按用户要求进行知识提炼和学习笔记，不声称所有视频专属产物都已适用于文档。独立文档的多轮问答可在加入课程后使用课程 Agent；首版不另建一套独立文档聊天产品。

## 10. 需求对照与复核结论

| 用户需求 | 对应交付 | 边界 |
|---|---|---|
| 不影响原来的功能 | §1.1 兼容矩阵、§7 回归门槛 | 保留原数据与契约，新增功能失败不改写旧状态 |
| 从视频扩展更多资料 | §3.1 独立资料、§3.2 格式矩阵 | 原视频全部能力 + 文档知识提炼；课程不是必选项 |
| 同课视频放在一个文件夹 | §4.1～4.2 课程/章节归档 | 逻辑文件夹，不复制或移动底层文件 |
| 保存知识笔记 | §4.3 自动保存、版本、导出、旧结果保存 | 保存不等于发布到知识库 |
| 用笔记形成新课程 Agent 的 RAG | §4.4 已发布笔记 + 原始证据 | 课程 Agent 独立，不替换 Video Agent |
| 期末针对性复习 | §4.5 重点、诊断、计划、练习闭环 | 区分课程重要性与个人掌握度 |
| PDF / Word / PPT 学习资料导入 | §3.2 + P2/P3 | 基础文字可落地；复杂公式、手写和图形专项后续处理 |

文档已检查需求覆盖、原功能兼容、数据归属、删除语义、格式限制、实现依赖和验收路径。实现是否真正无回归须在 P0 建立基线并逐阶段验证，不能仅凭设计承诺零影响。
